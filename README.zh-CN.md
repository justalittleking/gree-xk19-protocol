# 格力 XK19 协议

**GRZ4E-B（2009）· XK19 线控器 · FE/BA 变体 · RS-485 1200 8N1 · 只读**

![status: read-only](https://img.shields.io/badge/status-read--only-0f766e)
![protocol: partial](https://img.shields.io/badge/protocol-partial-d97706)
![board: GRZ4E-B](https://img.shields.io/badge/board-GRZ4E--B-1f5f8b)

这是 2009 年 GRZ4E-B 内机和 XK19 线控器之间的 1200 波特 RS-485 逆向记录，
附带一个树莓派只读看板。

不是格力官方项目，跟格力没关系。完整说明见 [DISCLAIMER.md](DISCLAIMER.md)。

状态：v0.1.0 只读版（2026-10-19）。

现在能读设定温度、模式和实际风速档。室温、X-FAN 设定、自动/手动风速还读不到。
往并联总线里写设定试过，没成功；下一步准备试双 UART MITM。

如果你的线控器发出 `7E 7E` 帧，那是另一个变体。我的抓包里没有 `7E 7E`，
只有 `FE` 空闲字节和 `BA AA CE 3E` / `E9 A6 CE 3E` payload。

## 范围

- 包含：只读解码、接线记录、本地看板。
- 不包含：厂商固件、云端/App 协议、写控制。写控制只是计划，还没验证。
- 只在一台 GRZ4E-B（2009）上测试过，其他批次可能用不同的帧。

## 当前环境

我现在用的是树莓派 3 Model B+ 加 CH340 USB-RS485，`/dev/ttyUSB0`。A/B 抽头，
AGND 建议接上做共模参考，12V 不接。ESP32 没有接到这台空调上。

| 阶段 | 硬件 | 状态 |
|---|---|---|
| 当前 | 树莓派 3 Model B+ + CH340 USB-RS485 | 只读 |
| 下一步 | ESP32 + 两路 RS485 + 旁路继电器 | 计划中，ESP32 还没接 |

仓库里的 ESP32/MITM 内容只是计划和测试方案，不是已经装好的东西。

## 现在能读到什么

| 字段 | 状态 | 说明 |
|---|---|---|
| 设定温度 | 已验证 | `STATUS +6`，`(0xFE - byte) / 4`，16–30℃ |
| 模式 | 部分验证 | 制冷/抽湿/送风现场试过；制热/自动还需要补样本 |
| 实际风速档 | 部分验证 | `FA / F6 / F2` = 1 / 2 / 3；自动和同档手动分不出来 |
| 运行态 | 实验性 | `STATUS +7`，还有几个值没分清 |
| 室温 | 没解出来 | 没找到稳定字段 |
| X-FAN 设定 | 没解出来 | 可能保存在面板本地，只在切换或关机时发 |
| X-FAN 吹干 | 低置信度 | 只在关机后的 `0xEE` 帧附近见过 |
| 写控制 | 没打通 | 并联注入失败；ESP32/MITM 是下一步 |

我不建议现在就把它当完整的空调集成用。只读设定温度、模式和实际风速，它能用。

## 协议

![状态帧和 E9 帧布局](docs/frame-layout.png)

串口参数是 1200 波特、8 数据位、无校验、1 停止位。帧长不固定，图里标了哪些
部分固定、哪些会变。下面是字段表。

### 状态帧外壳

| 长度 | 部分 | 值 |
| :---: | :--- | :--- |
| 0–4 字节（可选） | prefix | `06 00`、`1A FF`、`CE 00`、`3A 60 06 02` … |
| 0 或 3 字节 | marker | 通常是 `20 20 00`，有些帧没有 |
| 12 字节 | payload | 从 `BA AA CE 3E` 开始，到 `7E F9` 结束 |
| 12–19 字节 | 完整帧 | 抓包里常见 15–17 字节 |

payload 永远是 `BA` 到 `F9` 这 12 字节。prefix 和 `20 20 00` 不属于状态字段。

### 状态 payload

| 偏移 | 字节数 | 字段 | 例子 |
| :---: | :---: | :--- | :--- |
| `+0…+3` | 4 | signature | `BA AA CE 3E` |
| `+4` | 1 | type | `F2` |
| `+5` | 1 | mode | `74` = 制冷 |
| `+6` | 1 | setpoint | `96` = 26℃ |
| `+7` | 1 | run | `06` |
| `+8` | 1 | fan | `FA` = 1 档 |
| `+9` | 1 | flag | `BE` = 制冷类 |
| `+10…+11` | 2 | trailer | `7E F9` |

### 帧例子

| prefix | marker | payload | 状态 |
| :--- | :---: | :--- | :--- |
| `06 00` | `20 20 00` | `BA AA CE 3E F2 74 96 06 FA BE 7E F9` | 制冷 26℃，1 档 |
| `1A FF` | `20 20 00` | `BA AA CE 3E F2 74 9A 0A FA BE 7E F9` | 制冷 25℃，1 档 |
| `3A 60 06 02` | 无 | `BA AA CE 3E F2 74 9E 06 FA BE 7E F9` | 制冷 24℃，1 档 |
| `06 00` | `20 20 00` | `BA AA CE 3E F2 F4 92 EE EC BE 7E F9` | 关机/待机 27℃ |

### E9 帧

| 长度 | 部分 | 值 |
| :---: | :--- | :--- |
| 0–4 字节（可选） | prefix | 会变 |
| 0 或 3 字节 | marker | 有 `20 20 00` 时就是它 |
| 4 字节 | signature | `E9 A6 CE 3E` |
| 1 字节 | type | `F2` |
| 1 字节 | B5 | 实验性，不是干净的 blow 开关 |
| 1 字节 | B6 | 实验性，会漂 |
| 0–? 字节 | tail | `FE …`，E9 后面的 payload 是 7–9 字节 |

例子：

| 完整帧 | 说明 |
| :--- | :--- |
| `03 06 02 E9 A6 CE 3E F2 FC AC FE EE` | 没有 marker |
| `20 20 00 E9 A6 CE 3E F2 0C 5A FE EE` | 只有 marker |
| `5E FF 20 20 00 E9 A6 CE 3E F2 04 56 FE EE` | prefix 加 marker |

我按签名扫 `BA AA CE 3E`，读 12 字节并检查 `7E F9`，不按 `FE` 切帧。
`FE` 也可能是 payload，`STATUS +7` 在待机时就能是 `FE`。完整规则在
[docs/PROTOCOL.md](docs/PROTOCOL.md)。

## 接线

XK19 是四芯线。这台机器丝印是 `+12V B AGND A`，但不同批次顺序可能不一样，
接线前先用万用表确认，别信线色。

| 线 | 用途 | 接 USB-RS485？ |
|---|---|---|
| `+12V` | 内机给面板供电 | 不接，包起来 |
| `AGND` | 共地 | 接适配器 GND |
| `A` | RS-485 A | 接 |
| `B` | RS-485 B | 接 |

只读抽头用 1 拖 2 的 XHB 线并联在原线上。接 A、B，AGND 能接就接，12V 必须
悬空。A/B 极性对的时候 idle 是 `FE`；读到 `01` 就交换 A/B。

我现在只接 A/B。1200 波特、短线能跑，但不是长期最稳的接法。AGND 是信号参考，
不是 12V。接之前先量一下适配器 GND 和面板 AGND 之间的电压。

要控制的话，1 拖 2 不够。需要断开 A/B，保留 12V/AGND，串两路 RS485，再加
一个常闭旁路继电器。ESP32 桥还没有在这台机器上搭过。

引脚、接线图和继电器接法在 [docs/WIRING.md](docs/WIRING.md)。

## 快速开始

只想看界面，可以跳到第 2 步。真要用在空调上，先接只读抽头。

### 1. 接只读抽头

接线前先断电。把 4P 1 拖 2 线插在面板和原线之间。适配器那一支接 A、B，
AGND 能接就接，12V 包起来。插之前逐针确认顺序。

上电后在 1200 8N1 打开串口，idle 应该是 `FE`。如果读到 `01`，交换 A/B。

详细步骤见 [docs/WIRING.md](docs/WIRING.md)。

### 2. 不接硬件先看界面

```bash
python3 serve_demo.py
```

打开 <http://localhost:8765/?demo=1>，会回放 2026-10-18 的六个快照。

`serve_demo.py --mock` 用录下来的当前快照走实时接口；`serve_demo.py --source
http://PI:8080` 直接代理一台正在运行的树莓派。

### 3. 在 Pi 上跑

```bash
pip install -r requirements.txt
python3 pi_485_dashboard.py
```

打开 `http://<pi-address>:8080/`。

### 4. MITM 控制

这部分是计划，没有实测。动手前先看 [docs/CONTROL.md](docs/CONTROL.md) 和
[docs/WIRING.md](docs/WIRING.md)。旁路继电器没弄好之前，别让 ESP32 成为唯一
控制通道。

## 这个板子为什么麻烦

较新的 XK19 用 `7E 7E` 帧。我这台不是。完整抓包里一个 `7E 7E` 都没有，
新版本的字段表也套不上。搜 “XK19” 基本都会落到新版本。

我把这个 `FE / BA` 版本记下来，是因为网上没找到现成的资料。没把握的部分
都标成未知，早期几条错误结论也在发布前删掉了。

## 面板会纠正

我试过往并联总线里注入设定，没成功。注入后抓到过一帧基线里没有的：

```text
4A 00 20 20 00 BA AA CE 3E F2 74 96 02 FA BE 7E F9
```

它的设定字节是 26℃，是面板自己的值，不是我发进去的值。我只见过一次，所以
先当成假设：面板是主站，会把自己的状态重新发一遍。这个证据足够说明并联注入
不可行，但还不足以说已经解完了整套纠正协议。

下一步准备做双 UART MITM，把 ESP32 串在面板和内机之间，改面板发出去的帧，
同时用常闭继电器做旁路。ESP32 挂了，面板还能直接连回内机。

## 字段是怎么来的

字段不是一次猜出来的，是一轮一轮对出来的：

1. 抓整段总线；
2. 在面板上只改一个设置；
3. 对比前后帧；
4. 离线回放抓包；
5. 回真机上复核；
6. 把还没确认的东西记下来。

我也走过弯路：

- 以为总线是 `7E 7E` 头，实际一个都没有。
- 以为 `E9 B5` 是 blow 开关。某次 24℃ 对照里它从 `FC` 变成 `04`，但后来
  现场测试又不成立。
- 以为 `E9 B6` 是稳定的运行态。它其实会自己漂。
- 以为 `F6 FA` 是室温。它一直在抖，跟设定温度也对不上。

现在表里只留有抓包或现场复核支撑的字段，没把握的都标成实验性或未知。

## Home Assistant

看板目前只做只读监控：

- 暴露设定温度、模式、实际风速档和一个诊断用的运行态；
- 不要拿 `+6` 当室温，它是设定温度；
- 不要把 X-FAN 做成开关，周期状态帧里读不到这个设定；
- climate 需要 `current_temperature` 的话，接一个外部室温传感器。
